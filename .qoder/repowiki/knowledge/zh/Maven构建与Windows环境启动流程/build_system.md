## 1. 构建系统概览
本项目采用 **Apache Maven** 作为核心构建工具，基于 **Spring Boot 2.7.18** 框架。项目定位为单体应用（Monolith），打包格式为可执行 JAR (`jar`)。为了降低开发者的环境配置门槛，项目引入了 **Maven Wrapper** 机制，并提供了针对 Windows 平台的自动化启动脚本。

## 2. 核心构建配置
- **基础依赖管理**：通过 `pom.xml` 继承 `spring-boot-starter-parent` (v2.7.18)，统一管理 Spring 生态及相关第三方库（如 `commons-math3`, `gson`）的版本。
- **编译环境约束**：强制要求 **JDK 1.8** (`java.version=1.8`)，确保在较旧的服务器或工业控制环境中具备兼容性。
- **打包插件**：使用 `spring-boot-maven-plugin` 进行 Fat JAR 打包，将依赖库嵌入最终产物，实现“一键运行”。
- **版本策略**：当前版本固定为 `1.0.0`，未见动态版本号生成逻辑。

## 3. 自动化与环境适配
- **Maven Wrapper (`mvnw.cmd`)**：
  - 实现了构建工具的自包含。若本地未安装 Maven，脚本会自动从中央仓库下载指定版本（Apache Maven 3.9.6）的 Wrapper JAR。
  - 解决了不同开发者机器上 Maven 版本不一致导致的构建差异问题。
- **一键启动脚本 (`run.bat`)**：
  - **环境预检**：在执行构建前，自动检测系统是否安装 JDK 1.8。若缺失，会输出详细的安装指引及环境变量配置建议。
  - **编码处理**：通过 `chcp 65001` 强制切换控制台编码为 UTF-8，防止中文日志或界面出现乱码。
  - **构建即运行**：直接调用 `mvnw.cmd spring-boot:run`，省去了手动执行 `mvn package` 再 `java -jar` 的步骤，适合快速演示和本地调试。

## 4. 开发者规范与建议
1. **环境准备**：确保机器已安装 JDK 1.8 并正确配置 `JAVA_HOME`。虽然脚本有检查，但建议预先配置好以加快首次启动速度。
2. **构建命令**：
   - 开发调试：直接使用根目录下的 `run.bat`。
   - 生产打包：建议执行 `mvnw.cmd clean package` 生成独立的 JAR 文件。
3. **跨平台注意**：目前仅提供 Windows 批处理脚本。若在 Linux/macOS 环境下部署，需手动安装 Maven 或使用标准的 `mvn` 命令，并编写对应的 Shell 启动脚本。
4. **依赖管理**：新增依赖时，请在 `pom.xml` 中明确指定版本（除非由 Parent 管理），并保持 UTF-8 编码格式。
